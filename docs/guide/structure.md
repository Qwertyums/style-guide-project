# Структура документации

## Обязательные шаблоны

S01. Пользовательская инструкция должна содержать: назначение, область
применения, предварительные условия, нумерованные действия, ожидаемый
результат и решение возможных проблем. Для разных задач создают отдельные
инструкции: загрузка, распознавание, исправление, экспорт.

S02. Техническое описание должно содержать: назначение компонента, версию,
входные и выходные данные, алгоритм или последовательность взаимодействий,
ошибки, ограничения и способ проверки. API описывают только при его наличии
в спецификации: метод, путь, авторизация, параметры, ответ и коды ошибок.

S03. Протокол проверки должен содержать идентификатор, цель, окружение,
исходные данные, шаги, ожидаемый и фактический результаты, расчёт метрик,
критерий прохождения и вывод. Если тест не выполнялся, фактический результат
помечают «не выполнено»; его нельзя подменять ожидаемым.

## Организация разделов

S04. В начале страницы кратко объясните её назначение. Используйте один
заголовок первого уровня. Уровни не пропускают. В навигацию MkDocs включают
каждую содержательную страницу; названия должны соответствовать её теме.

S05. Дублируемые правила следует заменить ссылкой на основной раздел.
Внутренние ссылки должны вести на исходные `.md`-файлы или существующие якоря.
Оглавление сайта задаётся в `mkdocs.yml`, а оглавление страницы формируется
из заголовков. Порядок разделов должен соответствовать пути читателя к результату.
