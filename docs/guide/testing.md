# Документирование тестирования

Q01. Для воспроизводимости укажите версию приложения и модели, окружение,
настройки, источник данных и точную эталонную расшифровку. Для расчётного
примера без запуска приложения прямо обозначьте этот режим проверки.

Q02. Ожидаемый результат и критерий прохождения задают до выполнения теста.
Фактический результат записывают отдельно. Нельзя объявлять продукт
проверенным по расчёту на заранее заданной строке.

## Метрики распознавания

Q03. Долю ошибок на уровне символов (Character Error Rate, CER) вычисляют
как `(S + D + I) / N`, где S — замены, D — удаления, I — вставки,
N — число символов в эталоне. Используют минимальное редакционное расстояние
Левенштейна. Результат в процентах получают умножением на 100.

Q04. Для доли ошибок на уровне слов (Word Error Rate, WER) применяют ту же
формулу к последовательности слов. До сравнения фиксируют нормализацию:
регистр, пробелы, переносы строк, пунктуацию и правила разбиения на слова.
Если N равен нулю, метрику помечают «не определена», а не делят на ноль.
Из-за вставок CER и WER могут превышать 100 процентов.

Q05. На наборе документов суммируют число ошибок и длины эталонов, затем
делят суммы. Простое среднее процентов по строкам не эквивалентно этой метрике.
Показатели на небольшой учебной фразе нельзя обобщать на качество модели.

## Приёмка документации

Q06. Проверяйте отдельно содержание, оформление и воспроизводимость.
Линтер проверяет синтаксис, а не достоверность. В ревью должны быть
проверены терминология, условия действий, ожидаемый результат, ограничения
и отсутствие неподтверждённых заявлений.
