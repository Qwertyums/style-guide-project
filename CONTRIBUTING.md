# Участие в разработке руководства

## Как предложить изменение

Создайте issue с проблемой, затронутым правилом и примером до и после.
Для небольшой опечатки можно сразу открыть PR. Для нового обязательного
правила объясните, как автор и рецензент будут проверять соблюдение.

```sh
git switch main
git pull --ff-only
git switch -c codex/topic-name
```

Меняйте исходники в `docs/`. Не редактируйте сгенерированный каталог `site/`.
Один PR должен решать одну связанную задачу.

## Сообщения коммитов

Используйте Conventional Commits: `type(scope): краткое описание`.
Для текста — `docs`, для автоматизации — `ci`, для зависимостей — `build`.
Область необязательна. Пример: `docs(accessibility): clarify alternative text`.
Не объединяйте несвязанные изменения только ради одного коммита.

## Локальная проверка

В корне репозитория выполните команды для Windows PowerShell:

```powershell
python -m venv .venv
.venv\Scripts\python -m pip install -r requirements.txt
npm ci
npm run lint
.venv\Scripts\python -m mkdocs build --strict
.venv\Scripts\python -m mkdocs serve
```

В Linux и macOS замените `.venv\Scripts\python` на `.venv/bin/python`.
Сборка должна завершиться с кодом 0 без предупреждений. Откройте локальный
адрес, который показывает сервер, и проверьте навигацию и читаемость.
Остановите сервер сочетанием Ctrl+C.

## Как добавить раздел

1. Создайте файл `docs/guide/topic-name.md` с одним заголовком первого уровня.
2. Укажите область применения и добавьте правила с уникальными идентификаторами.
3. Приведите проверяемые примеры и ссылки на связанные разделы.
4. Добавьте страницу в `nav` файла `mkdocs.yml`.
5. Запустите линтинг и строгую сборку.
6. Сделайте коммит, отправьте ветку и создайте PR в `main`.

```sh
git add docs/guide/topic-name.md mkdocs.yml
git commit -m "docs: add topic rules"
git push -u origin codex/topic-name
```

## Ревью и слияние

В описании PR укажите проблему, изменённые правила, результат проверок
и ссылки на примеры. Рецензент проверяет достоверность, терминологию,
воспроизводимость и доступность. Каждый комментарий должен содержать
конкретное место, причину и предложение или уточняющий вопрос.

Для лабораторной работы обменяйтесь ссылками с другим студентом и оставьте
не менее трёх содержательных комментариев к его PR. Не подменяйте взаимное
ревью самопроверкой. Полученные замечания исправьте отдельным коммитом
в той же ветке и ответьте на каждое замечание.

Слияние выполняют только после одобрения независимого рецензента и успешного
завершения проверки `check`. После merge проверьте запуск `Documentation`,
успех задания `deploy` и наличие новой страницы на опубликованном сайте.
Если публикация не работает, сначала проверьте **Settings → Pages → Source**:
должно быть выбрано **GitHub Actions**.
